Claude và Obsidian: chọn plugin hay Claude Code cho hệ ghi chú?

So sánh plugin AI trong Obsidian với việc chạy Claude Code trên cả vault ghi chú: khi nào dùng cách nào, cách chuẩn bị, bảo vệ dữ liệu và các tác vụ mẫu.

Tác giả: Hữu Hùng · Xuất bản: 2026-04-23 · 7 phút đọc

Trả lời nhanh: Dùng plugin AI khi bạn muốn hỏi đáp hoặc viết ngay trong từng ghi chú. Dùng Claude Code khi cần làm việc trên nhiều ghi chú cùng lúc, như tìm ghi chú trùng, thêm thuộc tính, gom nhóm hay tạo mục lục. Trước khi cho AI sửa vault, hãy sao lưu bằng Git.

Vault của Obsidian thực chất là gì

Một vault Obsidian chỉ là một thư mục chứa các file Markdown (.md) trên máy bạn, kèm vài thư mục cấu hình. Chính đặc điểm này làm cho Claude Code dùng được ngay: nó đọc và ghi file trong thư mục như với một dự án code, không cần kết nối riêng với Obsidian. Bạn có thể mở vault trong Obsidian để đọc như bình thường trong khi Claude Code làm việc trên cùng thư mục.

Hai cách tiếp cận

  • Plugin AI trong Obsidian: nằm ngay trong giao diện ghi chú. Hợp với hỏi đáp về ghi chú đang mở, viết lại đoạn văn, tóm tắt. Thuận tiện cho thao tác nhỏ, nhưng thường chỉ làm trên phạm vi bạn chọn.
  • Claude Code chạy trên thư mục vault: làm việc trên cả cây thư mục. Hợp với tác vụ hàng loạt, có quy tắc và cần kiểm tra lại, nhưng phải dùng terminal.

Tên và tính năng của từng plugin thay đổi liên tục và tùy nhà phát triển, nên bạn hãy tự xem mô tả, đánh giá và quyền truy cập mà plugin yêu cầu trước khi cài.

Khi nào nên chọn cách nào

  • Chọn plugin nếu việc của bạn là viết, hỏi nhanh và sửa văn bản từng ghi chú một.
  • Chọn Claude Code nếu việc của bạn là tổ chức lại: đổi tên hàng loạt, thêm tiêu đề thuộc tính cho hàng trăm ghi chú, tìm các ghi chú nói cùng một ý, tạo ghi chú tổng hợp theo chủ đề.
  • Dùng cả hai là hoàn toàn bình thường: plugin cho việc hằng ngày, Claude Code cho dọn dẹp định kỳ.

Chuẩn bị trước khi cho Claude Code làm việc trên vault

  1. Sao lưu bằng Git. Khởi tạo Git trong thư mục vault và commit trạng thái hiện tại. Bạn xem lại mọi thay đổi bằng git diff và hoàn tác nếu AI sửa sai.
cd duong-dan/den/vault
git init
git add -A
git commit -m "Sao luu truoc khi dung AI"
  1. Loại trừ thư mục không muốn AI đụng tới. Dùng quy tắc từ chối trong .claude/settings.json cho các thư mục riêng tư.
  2. Viết CLAUDE.md mô tả quy ước của vault để AI làm đúng cách của bạn:
# Vault ghi chú cá nhân
- Ghi chú là file Markdown, tên theo dạng "Chủ đề - Ý chính".
- Mỗi ghi chú có phần thuộc tính (frontmatter) gồm: tags, created.
- Liên kết nội bộ dùng cú pháp [[Tên ghi chú]].
- Không sửa thư mục "Nhat-ky-rieng" và "Mat-khau".
- Luôn đề xuất kế hoạch trước, chỉ sửa khi tôi đồng ý.

Các tác vụ mẫu cho Claude Code

Hãy bắt đầu ở chế độ chỉ lập kế hoạch và kiểm tra trên một thư mục con nhỏ:

  • "Liệt kê các ghi chú thiếu thuộc tags, chưa sửa gì."
  • "Đề xuất các cặp ghi chú có nội dung gần giống nhau để tôi quyết định gộp."
  • "Tạo ghi chú mục lục cho thư mục Du-an, liên kết tới từng ghi chú bằng cú pháp wiki."
  • "Chuẩn hóa tên file theo quy ước trong CLAUDE.md, cho tôi xem danh sách đổi tên trước khi làm."

Rủi ro cần biết

  • Sửa hàng loạt rất dễ sai. Một quy tắc đổi tên sai có thể phá vỡ liên kết giữa các ghi chú. Luôn xem kế hoạch và dùng git diff.
  • Đồng bộ nhiều thiết bị. Nếu vault nằm trong thư mục đồng bộ đám mây, thay đổi hàng loạt có thể gây xung đột. Hãy làm khi các thiết bị khác không đang chỉnh sửa.
  • Quyền riêng tư. Nội dung các file Claude Code đọc được sẽ được gửi đi để xử lý. Đừng cho nó đọc ghi chú chứa mật khẩu, dữ liệu khách hàng hoặc thông tin nhạy cảm.
  • Đừng để AI tự "viết lại" ghi chú của bạn khi chưa cần. Ghi chú cá nhân mất giá trị nếu mất giọng văn của chính bạn.

Nên bắt đầu từ đâu

Nếu chưa dùng gì, hãy thử một plugin cho việc viết hằng ngày. Khi vault đủ lớn để bạn muốn "dọn nhà", chuyển sang Claude Code với bản sao lưu Git. Cách này tăng dần mức độ tin cậy mà không đánh cược toàn bộ ghi chú ngay từ đầu.
