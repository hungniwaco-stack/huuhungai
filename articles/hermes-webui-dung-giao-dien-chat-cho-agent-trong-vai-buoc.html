Hermes WebUI: dựng giao diện chat cho agent trong vài bước

Hướng dẫn cài Hermes WebUI, giao diện web cộng đồng cho Hermes Agent: yêu cầu, bootstrap hoặc Docker, đặt mật khẩu, truy cập từ xa an toàn và giới hạn đã biết.

Tác giả: Hữu Hùng · Xuất bản: 2026-04-28 · 7 phút đọc

Trả lời nhanh: Hermes WebUI (kho nesquena/hermes-webui) là giao diện web cộng đồng, không phải sản phẩm của Nous Research. Cài bằng python3 bootstrap.py hoặc Docker, mở http://127.0.0.1:8787. Mặc định không có mật khẩu và chỉ nghe ở máy bạn; nếu mở ra mạng thì phải đặt mật khẩu và nên đi qua SSH tunnel hoặc Tailscale.

Đừng nhầm ba thứ

  • Hermes WebUI (bài này): dự án cộng đồng của tác giả nesquena, giao diện ba khung gồm phiên, chat và tệp làm việc.
  • Bảng điều khiển chính thức (hermes dashboard): do Nous Research làm, dùng để quản trị cấu hình, phiên, khóa, cron.
  • Open WebUI: một ứng dụng chat độc lập kết nối tới máy chủ API của Hermes, xem Hermes Open WebUI với Docker và Ollama.

Tác giả Hermes WebUI nói rõ đây là dự án độc lập, không liên kết hay được Nous Research chứng thực. Ngoài ra còn có Hermes Workspace, một giao diện cộng đồng khác.

Yêu cầu

  • Hermes Agent đã cài (trình bootstrap sẽ thử cài bằng trình cài chính thức nếu thiếu).
  • Python 3.11 trở lên.
  • Linux, macOS hoặc WSL2. Windows gốc không được trình bootstrap hỗ trợ; README chỉ tới một hướng dẫn Windows do cộng đồng viết.
  • Docker nếu dùng cách cài bằng container.

Cách 1: bootstrap (README khuyến nghị)

git clone https://github.com/nesquena/hermes-webui.git hermes-webui
cd hermes-webui
python3 bootstrap.py

Trình bootstrap phát hiện hoặc cài Hermes Agent, tạo môi trường Python, khởi động máy chủ, đợi /health, mở trình duyệt (trừ khi thêm --no-browser) và chạy trình hướng dẫn thiết lập lần đầu.

Cách 2: chạy nền bằng ctl.sh

Hợp với máy ảo hay homelab:

./ctl.sh start
./ctl.sh status
./ctl.sh logs --lines 100
./ctl.sh restart
./ctl.sh stop

Tệp PID ghi ở ~/.hermes/webui.pid và nhật ký ở ~/.hermes/webui.log.

Cách 3: Docker

git clone https://github.com/nesquena/hermes-webui
cd hermes-webui
cp .env.docker.example .env
docker compose up -d

Sau đó mở http://localhost:8787. README còn có ảnh dựng sẵn ở ghcr.io/nesquena/hermes-webui và các tệp compose hai và ba container. Lưu ý một hạn chế đã biết: ở thiết lập hai container, công cụ chạy trong container của WebUI chứ không phải container của agent.

Kiểm tra

curl http://127.0.0.1:8787/health

Cổng mặc định là 8787, địa chỉ nghe mặc định là 127.0.0.1. Có thể đổi bằng các biến HERMES_WEBUI_PORT và HERMES_WEBUI_HOST.

Mật khẩu và truy cập từ xa

  • Xác thực mật khẩu mặc định tắt. Bật bằng biến HERMES_WEBUI_PASSWORD hoặc trong phần Settings. Có thể thêm passkey (WebAuthn) và đăng nhập OIDC tùy chọn.
  • Phiên đăng nhập dùng cookie HTTP-only có hiệu lực 24 giờ.
  • Để dùng từ máy khác, README ưu tiên Tailscale Serve (giữ WebUI ở loopback sau HTTPS chỉ trong mạng riêng). Cách đơn giản khác là đường hầm SSH:
ssh -N -L 8787:127.0.0.1:8787 user@host
  • Mở trực tiếp (HERMES_WEBUI_HOST=0.0.0.0 kèm mật khẩu) chỉ được coi là phương án cuối.

Vì giao diện này điều khiển một agent có thể chạy lệnh trên máy bạn, hãy xem nó như cửa vào máy chủ chứ không chỉ là trang web.

Tính năng chính theo README

Phản hồi dạng dòng chảy, thẻ công cụ và tác tử con, tìm, ghim, lưu trữ phiên, xuất nhập Markdown hoặc JSON, cây tệp với xem trước và sửa, nhãn nhánh Git, bộ chuyển profile, các khung Tasks (cron), Skills, Memory, Profiles, và nhập liệu giọng nói. Giao diện dùng được trên điện thoại.

Giới hạn đã biết

  • WebUI gắn chặt với phần bên trong của Hermes Agent. README khuyên nâng cấp WebUI và Hermes Agent cùng nhau, vì tổ hợp phiên bản lệch chưa được kiểm thử.
  • Một số tính năng phụ thuộc phía sau, ví dụ /goal trả mã 501 với một bộ điều hợp nhất định.
  • README ghi ranh giới API ổn định vẫn đang được làm.

Khi nào nên dùng

Nếu bạn muốn chat với agent từ điện thoại hoặc máy khác mà không dùng ứng dụng Desktop, và chấp nhận thêm một thành phần cộng đồng cần cập nhật. Nếu chỉ cần quản trị, bảng điều khiển chính thức là đủ.
