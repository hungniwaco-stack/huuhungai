DeepSeek và OpenClaw: thiết lập local gateway cho agent

Chạy mô hình cục bộ cho OpenClaw: runtime nên chọn, cấu hình nhà cung cấp tùy chỉnh, yêu cầu ngữ cảnh và gọi công cụ, kiểm tra từng lớp và rủi ro với mô hình nhỏ.

Tác giả: Hữu Hùng · Xuất bản: 2026-04-26 · 8 phút đọc

Trả lời nhanh: Để OpenClaw dùng mô hình chạy trên máy bạn, bạn chọn một runtime (llama.cpp, LM Studio, Ollama, vLLM...), khai báo nó như nhà cung cấp tùy chỉnh và kiểm tra mô hình gọi công cụ được. Tài liệu có ghi runtime ds4 cho DeepSeek V4 Flash trên macOS Metal. Rủi ro chính: mô hình nhỏ làm hỏng việc nhiều bước và không có bộ lọc an toàn như dịch vụ đám mây.

"Local gateway" nghĩa là gì ở đây

Có hai thứ dễ nhầm: Gateway của OpenClaw (tiến trình điều phối, mặc định ở cổng 18789) và máy chủ mô hình cục bộ (llama.cpp, LM Studio...). Bài này nói về cách OpenClaw dùng một máy chủ mô hình chạy trên chính máy bạn. Dùng mô hình qua đám mây xem DeepSeek, OpenClaw và Ollama Cloud.

Chọn runtime

Trang "Local models" của OpenClaw liệt kê các runtime nên dùng:

  • ds4: DeepSeek V4 Flash chạy cục bộ trên macOS Metal, có gọi công cụ kiểu OpenAI.
  • llama.cpp: chọn mô hình theo phần cứng, tải về có xác minh, máy chủ do OpenClaw quản lý.
  • LM Studio: thiết lập lần đầu dễ, có giao diện nạp mô hình và API Responses gốc.
  • Ollama: quy trình dòng lệnh, thư viện mô hình, dịch vụ systemd.
  • vLLM, SGLang, MLX: phục vụ thông lượng cao với endpoint tương thích OpenAI.
  • LiteLLM và proxy tùy chỉnh: mọi cổng có /v1/chat/completions kiểu OpenAI.

Cách dễ nhất: máy chủ cục bộ do OpenClaw quản lý

Cài plugin llama.cpp, chạy openclaw onboard và chọn Managed local server. Trước khi tải, trình thiết lập hiển thị máy chủ Gateway, mô hình, dung lượng tải và backend, rồi xác minh một lần gọi công cụ thật trước khi đổi mô hình mặc định. Nó kiểm tra RAM, bộ nhớ GPU và ổ đĩa thay vì đoán; các công thức mẫu dùng ngữ cảnh 64K, công thức nhỏ nhất cần tối thiểu 8 GiB bộ nhớ máy. Tài liệu nói rõ mức tối thiểu này "không đảm bảo vừa hay nhanh".

Khai báo thủ công nhà cung cấp tùy chỉnh

Với máy chủ có sẵn, dùng models.providers. Ví dụ từ tài liệu (LM Studio, cú pháp JSON5):

{
  agents: {
    defaults: {
      model: { primary: "lmstudio/my-local-model" },
      models: { "lmstudio/my-local-model": { alias: "Local" } },
    },
  },
  models: {
    providers: {
      lmstudio: {
        baseUrl: "http://localhost:1234/v1",
        apiKey: "${LM_API_TOKEN}",
        api: "openai-completions",
        timeoutSeconds: 300,
        models: [
          { id: "my-local-model", name: "Local Model", reasoning: false, input: ["text"],
            cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 },
            contextWindow: 200000, maxTokens: 8192 },
        ],
      },
    },
  },
}

Các trường chính: baseUrl (kèm /v1), apiKey (có thể tham chiếu biến môi trường), api (openai-completions, openai-responses, anthropic-messages) và models[] (cần ít nhất id). Máy chủ không xác thực thì đặt auth: "none" (chỉ với openai-completions). Mặc định cổng: LM Studio http://localhost:1234/v1, vLLM http://127.0.0.1:8000/v1, SGLang http://127.0.0.1:30000/v1, llama.cpp ví dụ http://127.0.0.1:8080/v1. Ollama được nhận ở http://127.0.0.1:11434 khi bạn bật bằng OLLAMA_API_KEY, ví dụ mô hình ollama/llama3.3. Hãy đặt contextWindow và maxTokens đúng giới hạn thật của mô hình.

Ngữ cảnh và gọi công cụ

  • Chừa chỗ cho toàn bộ lời nhắc, công cụ, lịch sử và đầu ra. Mô hình trả lời được câu ngắn vẫn có thể hỏng một lượt agent.
  • Kiểm tra mẫu chat và bộ phân tích của máy chủ hỗ trợ gọi công cụ; nếu không, công cụ hiện dạng chữ, JSON, XML hoặc mảng tool_calls rỗng.
  • Cảnh báo khi ngữ cảnh còn dưới 20% cửa sổ, chặn cứng dưới 10%.
  • Phần so sánh yêu cầu ngữ cảnh của Hermes: 64K token, xem Ollama và Hermes.

Khi mô hình nạp được mà agent vẫn hỏng

Tài liệu gợi ý kiểm tra từng lớp: trước hết kênh truyền (transport), rồi việc dùng công cụ và ngân sách ngữ cảnh. Có lệnh openclaw infer model run --local và --gateway để tách lớp lỗi. Một số lưu ý khác: lần nạp mô hình đầu gây trễ khởi động; timeoutSeconds của nhà cung cấp không kéo dài được thời gian chờ của agent, nếu agents.defaults.timeoutSeconds thấp hơn thì phải nâng cả hai; trên WSL2 với Ollama và NVIDIA, tự khởi động có thể nạp lại mô hình lúc bật máy và ghim bộ nhớ, gây khởi động lại máy ảo liên tục.

Rủi ro quan trọng

  • Mô hình nhỏ hoặc lượng tử hóa mạnh có thể làm hỏng việc nhiều bước dù qua bài kiểm tra chữ đơn giản. Chọn bản lớn nhất phần cứng chịu được.
  • Tài liệu viết rõ: mô hình cục bộ không có bộ lọc an toàn của nhà cung cấp đám mây. Giữ quyền công cụ hẹp, giữ bật nén ngữ cảnh và áp dụng phòng thủ chèn lệnh (xem bài học bảo mật).
  • Chế độ "lean" gỡ bớt công cụ tùy chọn cho mô hình yếu là thủ thuật xử lý sự cố nâng cao, không phải mặc định.

Kết hợp cục bộ và đám mây

Đặt một mô hình đám mây làm chính, mô hình cục bộ và một mô hình đám mây khác làm dự phòng, hoặc đảo thứ tự để ưu tiên cục bộ, với models.mode: "merge" để giữ các mô hình đám mây làm dự phòng. Nhớ rằng dự phòng sang đám mây làm dữ liệu rời máy.
