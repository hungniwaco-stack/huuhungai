Hermes Open WebUI với Docker và Ollama: dựng giao diện AI nội bộ

Dựng giao diện chat cho Hermes Agent: chạy mô hình bằng Ollama, bật API server của Hermes rồi nối Open WebUI trong Docker, theo đúng tài liệu chính thức.

Tác giả: Hữu Hùng · Xuất bản: 2026-04-26 · 9 phút đọc

Trả lời nhanh: Hermes Agent là agent của Nous Research, không phải một mô hình. Để có giao diện chat kiểu web, bạn chạy mô hình bằng Ollama, trỏ Hermes tới Ollama, bật API server của Hermes (cổng 8642 theo mặc định), rồi nối Open WebUI chạy trong Docker tới API server đó.

Ba thành phần và cách chúng nối với nhau

  • Ollama chạy mô hình ngôn ngữ trên máy bạn.
  • Hermes Agent là agent tự động hóa (có bộ nhớ, kỹ năng, công cụ). Nó dùng mô hình do Ollama cung cấp. Hermes có sẵn một API server theo chuẩn tương thích OpenAI.
  • Open WebUI là giao diện chat chạy trong Docker. Nó kết nối tới API server của Hermes như thể đó là một dịch vụ OpenAI.

Luồng đi là: trình duyệt, đến Open WebUI, đến API server của Hermes, đến Ollama. Điểm khác với cách dùng Open WebUI thông thường là Open WebUI không nói chuyện thẳng với Ollama mà đi qua Hermes, nên bạn trò chuyện với agent (có công cụ, bộ nhớ) chứ không chỉ với mô hình trần.

Yêu cầu máy

Theo hướng dẫn chạy Hermes cục bộ với Ollama của Nous Research:

  • RAM tối thiểu 8 GB cho mô hình khoảng 3 tỷ tham số, và từ 32 GB trở lên cho mô hình từ 27 tỷ tham số.
  • Ít nhất 5 GB ổ đĩa trống cho một mô hình, và 30 GB trở lên nếu dùng nhiều mô hình.
  • Card đồ họa NVIDIA có từ 8 GB bộ nhớ là tùy chọn nhưng giúp nhanh hơn đáng kể.
  • Cần Docker cho Open WebUI.

Hermes hỗ trợ Linux, macOS, WSL2 và Windows. Hãy xem trang cài đặt chính thức để biết cách phù hợp với hệ điều hành của bạn.

Bước 1: Cài Ollama và tải một mô hình có hỗ trợ công cụ

curl -fsSL https://ollama.com/install.sh | sh
ollama --version
curl http://localhost:11434/api/tags

Lệnh đầu dành cho Linux (trên Windows và macOS, tải bộ cài từ ollama.com). Lệnh cuối xác nhận Ollama đang chạy. Với công việc agent, mô hình phải gọi được công cụ. Hướng dẫn của Hermes chỉ ra mô hình gemma4:31b là lựa chọn duy nhất trong danh sách của họ có gọi công cụ đáng tin cậy, còn các mô hình nhỏ hơn họ liệt kê chỉ trò chuyện được chứ không chạy được công cụ:

ollama pull gemma4:31b

Bước 2: Nâng độ dài ngữ cảnh lên 64.000 token

Theo tài liệu của Hermes, Ollama mặc định dùng ngữ cảnh 2048 token, trong khi Hermes cần ít nhất 64.000 token để dùng công cụ. Tạo một phiên bản mô hình với ngữ cảnh lớn hơn bằng Modelfile:

cat > Modelfile << 'EOF'
FROM gemma4:31b
PARAMETER num_ctx 64000
EOF
ollama create gemma4-64k -f Modelfile

Từ đây hãy dùng tên gemma4-64k thay cho gemma4:31b.

Bước 3: Cài và cấu hình Hermes

Cài Hermes theo hướng dẫn chính thức (ví dụ trên Linux, macOS hoặc WSL2):

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
hermes setup

Khi trình thiết lập hỏi, chọn Custom Endpoint và nhập:

  • Base URL: http://localhost:11434/v1
  • API Key: để trống hoặc nhập no-key
  • Model: gemma4-64k

Hoặc sửa trực tiếp file ~/.hermes/config.yaml:

model:
  default: "gemma4-64k"
  provider: "custom"
  base_url: "http://localhost:11434/v1"

Chạy thử bằng lệnh hermes để chắc chắn agent trả lời được trước khi sang bước sau.

Bước 4: Bật API server của Hermes

hermes config set API_SERVER_ENABLED true
hermes config set API_SERVER_KEY khoa-bi-mat-cua-ban
hermes gateway

Hãy thay khoa-bi-mat-cua-ban bằng một chuỗi dài và khó đoán. Khi chạy đúng, bạn sẽ thấy dòng cho biết API server đang lắng nghe ở http://127.0.0.1:8642. Kiểm tra bằng:

curl -s http://127.0.0.1:8642/health
curl -s -H "Authorization: Bearer khoa-bi-mat-cua-ban" http://127.0.0.1:8642/v1/models

Lệnh đầu phải trả về trạng thái ok. Lệnh thứ hai phải liệt kê một mô hình tên hermes-agent.

Bước 5: Chạy Open WebUI trong Docker

docker run -d -p 3000:8080 \
  -e OPENAI_API_BASE_URL=http://host.docker.internal:8642/v1 \
  -e OPENAI_API_KEY=khoa-bi-mat-cua-ban \
  -e ENABLE_OLLAMA_API=false \
  --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  --name open-webui \
  --restart always \
  ghcr.io/open-webui/open-webui:main

OPENAI_API_KEY phải trùng đúng với API_SERVER_KEY và không được để trống. ENABLE_OLLAMA_API=false ẩn kết nối Ollama mặc định, nếu không nó sẽ hiện trống trong danh sách mô hình. Lần khởi động đầu mất khoảng 15 đến 30 giây. Trên PowerShell, hãy viết lệnh trên một dòng.

Bước 6: Mở giao diện

Vào http://localhost:3000 và tạo tài khoản. Tài khoản đầu tiên là quản trị viên, nên hãy tự tạo ngay. Chọn hermes-agent trong danh sách mô hình và bắt đầu trò chuyện.

Nếu muốn cấu hình qua giao diện thay vì biến môi trường: vào Admin Settings, mục Connections, thêm kết nối OpenAI với URL http://host.docker.internal:8642/v1 và khóa là API_SERVER_KEY.

Cổng sử dụng

  • Hermes API server: cổng 8642.
  • Open WebUI: cổng 3000 trên máy của bạn, ánh xạ tới cổng 8080 trong container.

Trên Linux không có Docker Desktop, nếu host.docker.internal không phân giải được, hãy giữ cờ --add-host như trên, hoặc dùng --network=host với địa chỉ http://localhost:8642/v1.

Bảo mật: những điểm tài liệu nhấn mạnh

  • Công cụ chạy trên máy chủ chứa API server. Terminal, file, trình duyệt và MCP chạy ngay tại nơi Hermes chạy, không phải trên laptop của người dùng. Ai vào được giao diện chat có thể ra lệnh cho agent, nên hãy kiểm soát chặt tài khoản.
  • API server mặc định chỉ lắng nghe ở 127.0.0.1. Việc đổi địa chỉ lắng nghe làm thay đổi ai có thể truy cập, hãy cân nhắc kỹ.
  • Biến môi trường chỉ có tác dụng ở lần khởi động đầu của Open WebUI. Sau đó, thay đổi phải làm qua giao diện quản trị, hoặc xóa volume và bắt đầu lại.
  • Không mở cổng 3000 hay 8642 ra internet nếu chưa có HTTPS và xác thực phù hợp.

Lỗi thường gặp

  • /health không trả lời: khởi động lại gateway bằng hermes gateway stop && hermes gateway.
  • /v1/models trả về 401: khóa trong lời gọi không khớp với API_SERVER_KEY.
  • Không thấy hermes-agent trong danh sách: kiểm tra khóa và địa chỉ kết nối ở phần Connections.
  • Agent không chạy được công cụ hoặc in ra JSON thô: mô hình không hỗ trợ gọi công cụ, hoặc ngữ cảnh còn quá nhỏ. Làm lại Bước 2.
  • Phản hồi đầu tiên rất lâu: mô hình đang xử lý lời nhắc hệ thống và các công cụ, nhất là khi chỉ có CPU. Giữ mô hình luôn nạp trong bộ nhớ sẽ giúp.
